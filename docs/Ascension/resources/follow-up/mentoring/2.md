### Revue de l'avancement depuis le dernier RDV

État général : le groupe avance en parallèle des cours de 4e année.

Avancement :

- Décomposition en briques : faite pour la première fonctionnalité (analyse de pose et conseils), pas encore pour le reste.
- Architecture retenue pour l'analyse : le squelette est extrait frame par frame, puis agrégé en séquences de mouvements clés (début et fin). Ces séquences sont transmises à un LLM optimisé, sans forcément de fine-tuning, pour produire des conseils plus spécifiques. Pas encore implémenté.
- Données : Olivier met à jour le script de scraping de vidéos (YouTube, Instagram). La collecte est en pause, faute d'espace de stockage : le groupe attend un VPS d'Epitech et estime son besoin à 200–300 Go. Aucune image n'est annotée à ce stade.
- Répartition des rôles : Nicolas sur le mobile (Flutter), Jundo et Olivier sur l'IA, Lou et Christophe sur le serveur.
- Traitements : ils sont tous exécutés côté serveur par le worker Python. Le client mobile se contente d'afficher les résultats, donc aucune contrainte de calcul sur le téléphone.

Feedback donné :

- Analyse via LLM : je suis réservé sur l'envoi de gros volumes de JSON de keypoints à un LLM. Un modèle dédié à la recherche de l'enchaînement optimal paraît nécessaire.
- Test en séance : nous avons testé en direct un modèle de langage multimodal sur la photo d'un mur. Sans préparation, il a identifié la voie, proposé un enchaînement mains/pieds étape par étape jugé cohérent par le groupe, et même esquissé un visuel avec un personnage. Conclusion : le mode fantôme paraît plus atteignable qu'estimé lors de la première séance.
- Distillation : on peut générer un dataset avec un modèle frontière puis fine-tuner un modèle open source (type Gemma) déployé sur le serveur. Mais en track technique, le jury attendra un vrai travail de recherche sur les algorithmes et l'entraînement. Il ne faut donc pas s'appuyer uniquement sur des modèles sur étagère.
- Priorité : le path finding, prérequis commun au mode analyse et au mode fantôme :
            - entraîner un YOLO (v8) pour détecter toutes les prises ;
            - extraire la couleur dominante de chaque prise (OpenCV) ;
            - regrouper les prises par couleur et proximité pour reconstituer les voies, avec en dernier recours une validation par l'utilisateur.
- Séquencement des mouvements : une fois la voie isolée et les positions possibles fixées, le modèle n'a plus qu'à ordonner les mouvements, ce qui devrait améliorer nettement les résultats. À terme, explorer une approche déterministe ou ML. Piste : un LSTM, car la donnée est séquentielle. À partir de la voie et de l'état courant (positions des mains et des pieds), il prédit l'état suivant optimal. L'état final est toujours les deux mains sur la dernière prise.
